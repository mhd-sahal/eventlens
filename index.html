How to get your logs

  1. Open Windows Event Viewer (press Start, type Event Viewer).
  2. Go to Windows Logs → Security.
  3. Optionally use Filter Current Log… to pick a time range or Event IDs (for example 4624, 4625, 4720, 4726, 4728, 4732, 1102, 4688).
  4. Choose Save Filtered Log File As… (or Save All Events As…) and pick the CSV type.
  5. Upload that CSV here.

Important: account names, IP addresses and group names live inside each event's Message text. Depending on your Windows version, the CSV saved from Event Viewer may only contain the list columns (date, source, Event ID, task category) without the Message. If your file has no Message column, this tool will tell you, and most correlation will not be possible.

The reliable alternative is to export from PowerShell (run it as Administrator), which includes the Message:

Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4624,4625,4688,4720,4726,4728,4732,1102} -MaxEvents 5000 |
  Select-Object TimeCreated, Id, LevelDisplayName, ProviderName, MachineName, TaskDisplayName, Message |
  Export-Csv -Path "$env:USERPROFILE\Desktop\security-events.csv" -NoTypeInformation -Encoding UTF8

More detail, including 7045 and PowerShell 4104 exports, is in the README.

Only analyse logs from systems you own or are authorised to investigate.

How to Think Like a SOC Analyst

  1. Identify the event. What Event ID is it, and what does Windows say it means?
  2. Understand what happened. Read the message in plain English: who did what to whom.
  3. Identify the affected user or system. Which account and which computer?
  4. Determine whether the activity is expected. Is there a ticket, a change window, a known job?
  5. Look for related events. What happened just before and just after?
  6. Correlate authentication and privilege activity. Failed logons, then success, then account or group changes tell a story that no single event tells.
  7. Gather additional evidence. Endpoint tools, MFA logs, firewall logs, asking the user.
  8. Decide whether escalation is required. Close as benign, monitor, or hand to incident response.

One security event rarely tells the entire story. Analysts build context by correlating multiple events.

How the rules work

  • Repeated failed logons: at least the threshold number of 4625 events for one account (inside the time window if enabled).
  • Failed logons followed by success: the same account has a 4624 after those failures. High, unless the success came from a different source IP than the failures, then Medium.
  • New account granted privileges: a 4720 followed by a 4728 or 4732 for the same account. High if the group looks privileged (for example Administrators).
  • Security log cleared: any 1102 is High.
  • Administrative / privilege activity: a plain summary of account, group, service and log-clearing events. Unrelated users are never linked automatically.

Full explanations, false positives and limitations are in the README.
